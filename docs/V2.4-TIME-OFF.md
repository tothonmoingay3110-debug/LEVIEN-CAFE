# V2.4 — Time off requests

V2.4 adds role-protected date-range availability requests and connects approved
time off to the published schedule. It does not calculate paid leave, PTO
balances, attendance, payroll, or legal leave entitlement.

## Included

- Every Supabase Auth staff role can submit a future time-off request.
- A request may cover 1–31 calendar days and include an optional reason.
- Staff can view their own requests and cancel a pending request.
- Owner and Manager can see team requests and approve or decline pending items.
- Owner and Manager can cancel previously approved time off.
- Manager cannot review or cancel an Owner request.
- Approved time off appears as an OFF marker in the weekly Schedule.
- New shifts, edited shifts, and approved shift requests are blocked when the
  employee has approved time off on that date.
- Time off cannot be approved while official shifts still exist in its range;
  management must cancel or reassign those shifts first.

## Permissions

| Action | Owner | Manager | Supervisor | Staff |
| --- | --- | --- | --- | --- |
| View own requests | Yes | Yes | Yes | Yes |
| Submit own request | Yes | Yes | Yes | Yes |
| Cancel own pending request | Yes | Yes | Yes | Yes |
| View team requests | Yes | Yes | No | No |
| Approve/decline team requests | Yes | Yes | No | No |
| Manage an Owner request | Yes | No | No | No |

The legacy environment Owner can review team requests but cannot submit personal
time off because it does not have a `staff_profiles` record.

## 1. Apply the migration

V2.1A, V2.1B, and V2.2 must already be installed. In Supabase Dashboard → SQL
Editor, run the complete contents of:

`supabase/migrations/20260822000100_v2_4_time_off_requests.sql`

The migration creates `staff_time_off_requests`, supporting pending, approved,
declined, and cancelled states. RLS is enabled and direct browser access is
revoked; requests flow through the role-protected server API.

## 2. Staff workflow

1. Sign in to `/admin` with an individual staff email.
2. Open **Time Off**.
3. Choose **Request time off**.
4. Select the first and last day and optionally enter a reason.
5. Submit and follow the request status.
6. A pending request may be cancelled before management reviews it.

## 3. Owner/Manager workflow

1. Open **Time Off** to see team requests.
2. Use status tabs to focus on Pending or Approved items.
3. Choose **Approve** or **Decline**.
4. If approval reports existing shifts, open Schedule and cancel or reassign
   those shifts, then approve again.
5. Use **Cancel approval** if an approved unavailable range is no longer needed.

## 4. Verification checklist

- Staff sees only personal requests.
- Owner/Manager sees all permitted team requests.
- Manager actions are unavailable on Owner requests.
- A range longer than 31 days is rejected.
- Overlapping pending/approved requests are rejected.
- Approved dates appear in the weekly schedule.
- Direct, edited, and request-approved shifts cannot overlap approved time off.
- Approval fails while scheduled shifts remain inside the requested date range.
- Staff/Supervisor cannot call management review actions directly.

## Important limitation

Time off means unavailable for scheduling only. The application does not decide
whether an absence is paid or unpaid and does not change labor-cost forecasts
until published shifts are cancelled or reassigned.
