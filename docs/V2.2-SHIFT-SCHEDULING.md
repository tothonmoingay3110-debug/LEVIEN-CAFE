# V2.2 — Shift registration and work scheduling

V2.2 adds date-specific shift registration and a published weekly work schedule
to the role-protected Admin workspace. It does not collect attendance, clock-in,
clock-out, location, or timesheet data.

## Included

- Every staff role can open Schedule after completing any required first-login
  password change.
- Staff can register a preferred date, start time, end time, and optional note.
- Staff can see their own requests and cancel a pending request.
- Staff can see only their own published shifts and weekly total.
- Owner and Manager can see the full team schedule and all requests.
- Owner and Manager can approve or decline requests.
- Approving a request publishes the matching work shift automatically.
- Owner and Manager can directly create, edit, reassign, or cancel work shifts.
- The server rejects overlapping published shifts for the same employee.
- Requests are date-specific and may be submitted up to 120 days ahead.

## Role rules

| Action | Owner | Manager | Supervisor | Staff |
| --- | --- | --- | --- | --- |
| View own schedule | Yes | Yes | Yes | Yes |
| Register own preferred shift | Yes | Yes | Yes | Yes |
| Cancel own pending request | Yes | Yes | Yes | Yes |
| View full team schedule | Yes | Yes | No | No |
| Approve/decline requests | Yes | Yes | No | No |
| Create/edit/cancel work shifts | Yes | Yes | No | No |
| Manage an Owner's shifts | Yes | No | No | No |

The legacy environment Owner can manage team schedules but cannot submit a
personal request because it has no `staff_profiles` identity. Use the Supabase
Auth Owner account for normal scheduling.

## 1. Apply the migration

V2.1A and V2.1B must already be installed. In Supabase Dashboard → SQL Editor,
run the complete contents of:

`supabase/migrations/20260816000300_v2_2_shift_scheduling.sql`

This creates:

- `staff_shift_requests` for employee registrations and review status.
- `staff_shifts` for the official published schedule.

Both tables use RLS and deny direct anonymous/authenticated browser access. The
server applies role checks with the service role.

## 2. Staff workflow

1. Sign in to `/admin` with an individual staff email.
2. Open **Schedule**.
3. Choose **Register my shift** or the plus button on a future date.
4. Enter the preferred start/end time and an optional note.
5. Submit and wait for Owner or Manager review.
6. An approved request appears in the published weekly calendar.

A request is availability/preference, not a confirmed work assignment, until
its status becomes Approved.

## 3. Owner/Manager workflow

1. Open **Schedule** to see the full week and pending requests.
2. Choose **Approve** to publish a requested shift or **Decline** to reject it.
3. Use **Add work shift** to assign a shift without a request.
4. Click a published shift to edit employee, date, time, station, or note.
5. Use **Cancel shift** when an assignment should be removed from the schedule.

The API prevents overlapping official shifts for the same employee. Multiple
employees may work during the same time range.

## 4. Verification checklist

- Staff sees only their own shifts and requests.
- Staff cannot call manager scheduling actions directly.
- Owner/Manager sees active and inactive employee names for schedule history,
  but only active employees can receive new assignments.
- Manager cannot create or change an Owner shift.
- Approving a request creates exactly one official shift.
- Conflicting shifts return a clear overlap error.
- Cancelling an official shift removes it from the published calendar.
- Navigation and API stay locked until a temporary password is replaced.
- No attendance or clock-in fields exist.

## Operational note

The application validates dates against the café's `America/New_York` calendar.
The weekly screen runs Monday through Sunday. Planned weekly hours and hourly
pay remain separate private compensation data from V2.1B.

V2.4 adds approved time-off markers to the weekly schedule and prevents new or
updated shifts from overlapping approved unavailable dates.

V2.5 adds a management-only Copy week action that safely reuses a published
seven-day schedule without overwriting existing target shifts.
