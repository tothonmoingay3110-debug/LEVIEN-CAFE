# V2.1B — Employee management

V2.1B lets an Owner or Manager create and maintain employee accounts from the
Admin workspace. Normal employee creation no longer requires Supabase Dashboard
access after the first Owner has been established.

There is no attendance or clock-in feature in this release.

## Included

- Create individual Supabase Auth employee accounts.
- Store employee name, email, phone, role, active status, planned weekly hours,
  and hourly pay.
- Show hours, pay rate, and estimated weekly pay only to Owner and Manager.
- Edit an employee's profile, role, hours, and pay.
- Lock or reactivate an employee account.
- Generate a temporary password when an account is created or reset.
- Require the employee to replace the temporary password at first login.
- Restrict a first-login session to My Account until the password is changed.

## Permissions

| Action | Owner | Manager | Supervisor | Staff |
| --- | --- | --- | --- | --- |
| Open Employees | Yes | Yes | No | No |
| View hours and pay | Yes | Yes | No | No |
| Create Manager, Supervisor, Staff | Yes | Yes | No | No |
| Create or manage Owner | Yes | No | No | No |
| Lock/reset other permitted accounts | Yes | Yes | No | No |
| Change own password | Yes | Yes | Yes | Yes |

Staff and Supervisor accounts can use the operations dashboard, view online
orders, and update order status. They cannot manage products, website content,
employee accounts, roles, hours, or compensation.

An Owner or Manager cannot lock their own account or change their own role.
They must use My Account to change their own password.

## 1. Apply the migration

V2.1A must already be installed. In Supabase Dashboard → SQL Editor, run the
complete contents of:

`supabase/migrations/20260816000200_v2_1b_employee_management.sql`

The migration adds `phone` and `must_change_password` to `staff_profiles` and
creates the private `staff_compensation` table.

## 2. Create an employee

1. Sign in to `/admin` as an Owner or Manager.
2. Open **Employees**.
3. Choose **Add employee**.
4. Enter name, email, phone, role, hourly pay, and planned weekly hours.
5. Save and copy the temporary credentials before closing the dialog.
6. Give those credentials to the employee through a trusted channel.

The temporary password is shown once. It cannot be recovered later; use
**Reset password** to create a different one.

## 3. First employee login

1. The employee signs in at `/admin` with their email and temporary password.
2. Only **My Account** is available.
3. They enter the temporary password as the current password and choose a new
   password with at least 12 characters, uppercase, lowercase, number, and
   symbol.
4. Their role-authorized workspace becomes available after the change succeeds.

## 4. Verification checklist

- Owner can create and edit every role.
- Manager can create Manager, Supervisor, and Staff, but cannot manage Owner.
- Supervisor and Staff cannot open Employees or call its API.
- Hours and pay are absent from staff session responses.
- Locked employees cannot start a new Admin session.
- Resetting another employee creates a new one-time temporary password.
- A temporary-password user cannot access protected Admin APIs until changing it.

## Security notes

- Auth account creation and administrative password reset run only on the
  server through the Supabase service role.
- `SUPABASE_SERVICE_ROLE_KEY` must remain server-only.
- `staff_compensation` has RLS enabled and grants no direct access to anonymous
  or authenticated browser clients.
- Public user signup should remain disabled.
- Keep the legacy Owner environment credentials until the Supabase Auth Owner
  and V2.1B flow have both been tested in production.
